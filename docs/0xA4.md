# DATUM `0xA4` GWMigration (alluded — Stage 2+)

## What it is

Luke’s DATUM Prime → Gateway message in the ABW set (opcode **`0xA4`**).
Intent (as discussed with iohzrd): **migrate a gateway’s mining relationship**
to another DATUM for a while (maintenance), then **return home**.

That is the clean **per-session forward** for **DATUM gateways** (software you
control) — not an ASIC `client.reconnect` lottery.

## Relation to this repo

| Plane | Mechanism in `pool-overflow` |
|---|---|
| SV1 ASIC → pool valve | Authorize-peek + opaque line-pump (Stage 1) |
| DATUM GW ↔ Prime | Follow **`0xA4`** when the gateway implements it (Stage 2) |

`overflow-core::DatumMigrationHint` is a placeholder for control-plane bookkeeping
(home peer, temporary peer, TTL). Wire format + crypto stay in the DATUM stack
(Ocean/CONVOY/ratum); this agent should **invoke or honor** migrate, not re-spec it.

## Status in the wild

- Designed for maintenance failover; same knob works for load-share.  
- Some gateways (e.g. ratum notes) **log `0xA4` without following** today.  
- Until follow exists: SV1 pump remains the portable overflow path.

## Implementation stance

- **Do not fake** `0xA4` in Stage 1.  
- **Do** keep types/docs so DATUM overflow plugs in without redesign.  
- When implementing: per-session migrate, sticky return-home, never mid-job splice
  without protocol support.
